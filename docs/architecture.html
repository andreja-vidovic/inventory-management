Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a FastAPI service backed by in-memory JSON data.

System architecture

Three tiers, two processes, no database.

Tech stack

Dependencies as declared in client/package.json and server/pyproject.toml.

Frontend

  • Vue 3 (Composition API)
  • Vue Router 4
  • Axios
  • Vite 8 dev server and build
  • Custom SVG charts, CSS Grid layouts
  • English and Japanese locales

Backend

  • Python 3.11+
  • FastAPI
  • Uvicorn
  • Pydantic 2 models
  • CORS open to all origins (dev only)

Data

  • JSON files: inventory, orders, demand, backlog, spending, transactions, purchase orders
  • No database or persistence

Tooling

  • uv for Python environments
  • pytest + FastAPI TestClient (tests/backend)
  • Claude Code agents, skills and MCP config in .claude/

Data flow

How a filter change reaches the screen.

  1. User changes a filterTime period, warehouse, category or order status in the filter bar; state lives in the useFilters composable.
  2. View calls the API clientclient/src/api.js builds query params and skips any filter set to all.
  3. FastAPI route receives the requestOptional query parameters on endpoints such as /api/orders or /api/dashboard/summary.
  4. Data is filtered in memoryLists loaded by mock_data.py are filtered sequentially, without mutating the originals.
  5. Pydantic validates the responseModels in main.py enforce the shape before JSON is returned.
  6. Vue updates the UIRaw data is stored in refs; derived values (totals, chart series) are computed properties that re-render automatically.
